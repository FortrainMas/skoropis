# Статус и план

Главная цель — распознавание Макаровки. Digital Peter нужен как дополнительные данные для
обучения: размеченных строк в нём примерно в 7 раз больше. Его собственные метрики важны только как
проверка, что обучение работает (с ними есть опубликованные цифры для сравнения).

## Что готово

| что | где | проверено |
|---|---|---|
| загрузка данных, разбиение Макаровки по страницам | `src/diploma/data.py`, `splits/makarov.json` | тесты |
| метрики и оценка любой модели | `src/diploma/evaluation.py`, `diploma eval` | тесты, прогоны E001 |
| описание валидации | [validation.md](validation.md) | — |
| E001: готовая модель Kansallisarkisto без дообучения | [E001](experiments/E001-kansallisarkisto-zeroshot.md) | Макаровка 19.5% CER, Peter 64% |
| бейзлайн CRNN + CTC и его обучение | `src/diploma/models/crnn.py`, `src/diploma/training.py` | на CPU: за 400 шагов выучивает 8 строк без ошибок |
| дообучение Kansallisarkisto на наших строках | `src/diploma/trocr_training.py`, `diploma train-trocr` | тесты на крошечной модели; на настоящей — шаг обучения, сохранение и оценка на CPU |
| прогон всех экспериментов на сервере одной командой | `scripts/server_run.sh` | только синтаксис: на GPU ещё не запускался |

Не сделано: обучение на GPU, декодирование с языковой моделью, нарезка неразмеченных страниц
на строки (нужна для псевдоразметки; есть готовая открытая модель, см. «Какие ещё данные»),
своя трансформерная архитектура, удаление дублей из разметки.

## Запуск на сервере

Сервер — одна RTX 4090 (24 ГБ) или T4 (16 ГБ). Что нужно:

- Драйвер NVIDIA версии 525 или новее. На Linux `uv sync` ставит torch 2.14.1, собранный под
  CUDA 12.6 (так задано в `pyproject.toml`): ему хватает такого драйвера, и он работает и на
  4090, и на T4. Сборка по умолчанию, под CUDA 13, требует драйвер 580+, которого во многих
  облачных образах ещё нет. Первым шагом скрипт проверяет, что torch видит карту и считает на ней.
- На картах с памятью меньше 20 ГБ скрипт сам уменьшает батч дообучения Kansallisarkisto
  вдвое и вдвое удлиняет накопление градиентов: на шаг оптимизатора по-прежнему 16 строк.
- Интернет: при первом запуске скачиваются пакеты (около 3–4 ГБ, в основном torch с CUDA),
  модель Kansallisarkisto (2.4 ГБ) и веса ResNet34 (83 МБ). Если Hugging Face с сервера
  недоступен, модель можно привезти из кэша ноутбука: папку
  `~/.cache/huggingface/hub/models--Kansallisarkisto--cyrillic-large-handwritten` скопировать
  в то же место на сервере.
- Данные: `data/strings` (40 МБ) и `data/digital-peter` (970 МБ). Фото страниц `data/raw`
  (1 ГБ) для этих экспериментов не нужны. Если данные лежат не в `data/` рядом с кодом, путь
  задаётся переменной `DIPLOMA_DATA`.
- Около 20 ГБ на диске: окружение, данные, модель Kansallisarkisto (2.4 ГБ) и её две
  дообученные копии (по 2.4 ГБ), чекпойнты CRNN (по ~45 МБ).

Код едет через git, данные — отдельно: их в репозитории нет. Это 22 тысячи файлов, и по
одному они копируются долго, поэтому на ноутбуке их сначала собирают в один архив (из корня
репозитория; `SERVER` — адрес сервера, как для `ssh`):

```bash
tar -cf data/server-data.tar -C data strings digital-peter
scp data/server-data.tar SERVER:
```

На сервере:

```bash
git clone <адрес репозитория> diploma && cd diploma
mkdir -p data && tar -xf ~/server-data.tar -C data && rm ~/server-data.tar
nvidia-smi    # «Driver Version» — 525 или выше; карту не занимают чужие процессы
curl -LsSf https://astral.sh/uv/install.sh | sh    # если uv ещё нет
tmux new -s htr 'bash scripts/server_run.sh; bash'
```

`tmux` нужен, чтобы прогон не оборвался вместе с SSH: отключиться — `Ctrl+B`, затем `D`,
вернуться — `tmux attach -t htr`. Сначала скрипт проверяет окружение (GPU, данные, тесты) и
при проблеме сразу останавливается. Потом идут эксперименты; упавший шаг не останавливает
остальные. После каждой эпохи обучение печатает CER на val и сколько примерно осталось.

Назад забрать `runs/`, `logs/` и историю обучения из `checkpoints/`; сами веса — по желанию.
На сервере, в `diploma`:

```bash
tar -cf ~/results.tar runs logs checkpoints/*/history.jsonl checkpoints/*/config.json
```

На ноутбуке, из корня репозитория:

```bash
scp SERVER:results.tar . && tar -xf results.tar && rm results.tar
```

### Сколько это займёт

Оценка по замерам на CPU. CRNN тратит около 110 млрд операций на строку Peter за проход
вперёд и назад, Kansallisarkisto — около 2.4 трлн на строку Макаровки (с учётом пересчёта
активаций ради экономии памяти); 4090 в bf16 на такой сети даёт, по опыту, 60–80 трлн операций в секунду.
Загрузка картинки с аугментацией — около 11 мс на одно ядро процессора; скрипт запускает
столько процессов загрузки, сколько у сервера ядер (но не больше 16). На быстрой карте
загрузка и вычисления сравнимы по времени, поэтому многое зависит от процессора сервера.
Строки собираются в батчи по ширине, поэтому на белые поля уходит лишь 2% вычислений. Память:
батч из 32 строк занимает несколько гигабайт из 24.

| шаг | эпох | на эпоху, 4090 | всего, 4090 | всего, T4 |
|---|---:|---:|---:|---:|
| установка, проверки, тесты | — | — | 5–10 мин | 5–10 мин |
| E004: дообучение Kansallisarkisto на Макаровке целиком | 20 | ~40 с | ~15–20 мин | ~1 ч |
| E004: то же, первые 6 эпох учится только энкодер | 20 | ~35 с | ~15 мин | ~50 мин |
| E002: CRNN на Peter | 60 | ~15 с | ~15 мин | ~50 мин |
| E003: CRNN на Макаровке с нуля | 100 | ~3 с | ~5 мин | ~15–20 мин |
| E003: дообучение модели E002 на Макаровке | 60 | ~3 с | ~3 мин | ~10 мин |
| E003: Peter и Макаровка вместе (Макаровка ×4) | 60 | ~20 с | ~20 мин | ~1–1.2 ч |
| оценка на тестах | — | — | ~2 мин | ~5–10 мин |
| **всего** | | | **~1.5 ч** | **~5–5.5 ч** |

Это оценка, ошибка может быть до полутора раз в обе стороны. Настоящее время на эпоху будет
видно в логе после первой эпохи.

T4 медленнее 4090 примерно в 3–4 раза: тензорные ядра дают 65 трлн операций в секунду в fp16
против 165 у 4090 в bf16, память — 320 ГБ/с против 1008. bf16 на T4 нет, поэтому обучение идёт
в fp16 с масштабированием потерь (`mixed_precision` в `src/diploma/training.py`). Если время
аренды ограничено, хватит первых двух часов: за них досчитается E004, главный эксперимент.

Для сравнения, ноутбук (Ryzen 5 4600H, замер шага обучения на строках Макаровки): CRNN —
1.4 с на строку, около 20 минут на эпоху Макаровки; Kansallisarkisto целиком — 16 с на строку,
около 3.7 часа на эпоху; с замороженным энкодером — 5.2 с на строку, около 1.3 часа на эпоху.
Весь план на ноутбуке занял бы недели.

E004 идёт первым: для Макаровки это самый вероятный кандидат на лучший результат, и если
сессию придётся прервать, он уже будет посчитан.

## Что ждём и что делаем по результатам

Опорные точки: готовая модель без дообучения даёт на тесте Макаровки 19.5% CER (15.7% без
учёта орфографии, регистра и пунктуации). На Digital Peter у CRNN в статье датасета 5.7%,
у лучших решений с сильными аугментациями — около 2.5%.

**1. Проверяем, что обучение работает: E002 на `peter:test`.**

- 3–7% CER — норма для нашего рецепта, идём дальше.
- больше 10% — что-то не так с обучением (learning rate, число эпох, аугментации). Чиним это
  до того, как делать выводы по Макаровке.

**2. Какая модель лучше на Макаровке: E004 против E003.**

Сравниваем лучший вариант дообученной Kansallisarkisto (E004) с лучшим вариантом CRNN (E003)
на `makarov:test`.

- **E004 заметно лучше**, разница больше доверительного интервала. Значит, знания большой
  модели о почерке эпохи важнее, чем специализированная маленькая сеть. Дальше развиваем её
  (см. «Что можно сделать с моделью Kansallisarkisto»), а CRNN остаётся бейзлайном.
- **Примерно одинаково.** Маленькая CRNN справляется не хуже и в 50 раз меньше, а значит,
  быстрее и дешевле в экспериментах. Развиваем её: языковая модель, псевдоразметка, своя
  архитектура.

**3. Сколько осталось до цели: лучший CER на `makarov:test`.**

- **Меньше 8%.** Модель уже полезна. Дальше:
  - декодирование со словарём или символьной языковой моделью (на Peter такое давало −40%
    ошибок);
  - псевдоразметка 520 неразмеченных страниц по статье (сначала нужна нарезка страниц на
    строки);
  - своя архитектура против лучшей модели в тех же условиях.
- **8–15%.** Упираемся в данные: 807 строк обучения — это мало. Дальше:
  - словарь или языковая модель при декодировании;
  - разметить ещё страниц: каждая страница — около 37 строк, то есть +4.5% к обучающей
    выборке;
  - добавить близкие по эпохе датасеты (см. «Какие ещё данные»).
- **Больше 15%.** Не лучше готовой модели без дообучения — значит, что-то не так с
  обучением. Разбираемся по `history.jsonl` и логам, прежде чем идти дальше.

**4. Помогает ли Peter Макаровке.** Сравниваем три варианта E003:

- дообучение с Peter или совместное обучение заметно лучше обучения с нуля, то есть разница
  больше доверительного интервала. Значит, чужой почерк помогает — имеет смысл добавлять
  ещё данные: синтетику дореформенным текстом, другие кириллические датасеты;
- разницы нет. Peter слишком далёк от Макаровки (E001 на это намекает), и силы лучше
  тратить на данные самой Макаровки: разметку и псевдоразметку.

**5. Когда браться за псевдоразметку.** Когда у лучшей модели CER на 20% самых уверенных
строк `makarov:val` опустится примерно до 2–3%. Тогда добавленные строки будут почти чистыми.
Сейчас у готовой модели там 9% — рано.

## Что можно сделать с моделью Kansallisarkisto

Устройство модели (разобрали веса):

| часть | что это | параметров |
|---|---|---:|
| энкодер | DINOv2-large, 24 слоя; строка растягивается до 182×1022 и режется на 13×73 = 949 квадратов по 14 пикселей | 304 млн |
| декодер | ruRoBERTa-large, обрезанная до 12 слоёв из 24 | 306 млн |
| — словари токенов на входе и на выходе | по 51.5 млн, не общие | 103 млн |
| — cross-attention (декодер смотрит на энкодер) | | 50 млн |

Учили её в два этапа. Сначала базовая модель
[`cyrillic-large-stage1`](https://huggingface.co/Kansallisarkisto/cyrillic-large-stage1):
138.6 млн синтетических строк, нарисованных 898 кириллическими шрифтами (почти все печатные,
рукописных мало). Тексты — исторические, XVIII–XX веков, вперемешку в дореформенной и
современной орфографии. На картинках «ѣ» и «і» были, а в метках их заменили на «е» и «и», так
что модель научилась видеть «ѣ» и писать «е». Затем 80 эпох на 56.6 тысячи архивных
рукописных строк; первые 11 эпох декодер был заморожен, чтобы энкодер привык к рукописи и не
испортил языковую модель. Токенизатор — byte-level BPE на 50 тысяч токенов от ruRoBERTa. Современный
текст ему удобен («дело» — один токен), дореформенный дробится («дѣло» — три).

Идеи, по убыванию ожидаемой пользы:

1. **Дообучение целиком и по рецепту авторов.** Уже в серверном прогоне (E004).
2. **Энкодер плюс CTC вместо декодера.** Энкодер уже читает почерк эпохи. Если поставить на
   него посимвольную CTC-голову, модель не сможет дописать текст, которого нет на картинке
   (как «Маннергеймъ» в E001), «ѣ» станет обычным символом алфавита, распознавание ускорится
   в несколько раз (нет пошаговой генерации), а уверенность будет по каждому символу — это
   удобно для псевдоразметки. Подвох: 73 столбца на строку — около двух на символ, для CTC
   мало. DINOv2 умеет растягивать позиционные эмбеддинги, так что вход можно сделать шире,
   например 182×2044 (146 столбцов). Хороший кандидат на «свою архитектуру»: сравнить в
   одинаковых условиях CRNN (свёртки с весами ImageNet), энкодер архивной модели с CTC и
   полную модель энкодер–декодер.
3. **CTC и декодер вместе**, как в распознавании речи: обе головы учатся одновременно, а при
   генерации CTC штрафует варианты, которых не видно на картинке. Это против галлюцинаций,
   но сложнее в реализации — после пункта 2.
4. **Более широкий вход сам по себе.** Модель растягивает любую строку до 182×1022. Строки
   Макаровки — примерно 10:1, и при сжатии до 5.6:1 буквы становятся почти вдвое уже.
5. **Токенизатор.** Дореформенные слова дробятся на редкие куски, и языковые привычки
   декодера тянут к современному написанию. Дообучение это отчасти лечит; добавлять новые
   токены — в последнюю очередь.

## Какие ещё данные

Открытых размеченных строк русской рукописи XIX — начала XX века в дореформенной орфографии
мы не нашли. Всё близкое по эпохе существует, но не выложено:

- **Обучающие данные Kansallisarkisto.** По новостям проекта ArchXAI — больше 1700 страниц
  русских документов 1809–1917 годов из архивов Финляндии (метрические книги, бумаги высших
  органов Великого княжества Финляндского). Не опубликованы; контакты авторов есть на
  карточках моделей. Можно написать и попросить.
- **Модели Transkribus** «Russian Generic Handwriting 2» (148.8 тысячи строк, конец XIX —
  начало XX века) и архив Рычкова (14.9 тысячи строк, 1910-е, дореформенная орфография) — есть
  только модели внутри платной платформы, данных нет.
- **Работа «HTR for Russian Empire Period Manuscripts»** (подана на ICLR 2026). По выдаче
  поиска — около 38.5 тысячи строк в дореформенной орфографии; открыты ли данные, проверить не
  удалось. Тоже стоит написать авторам.

Что открыто и чем можно воспользоваться:

- **Наши 520 неразмеченных страниц.** Ближе данных не бывает. Нарезать их на строки можно
  открытой моделью Kansallisarkisto
  [`rfdetr-textline-textregion-detection-2xl`](https://huggingface.co/Kansallisarkisto/rfdetr-textline-textregion-detection-2xl)
  (Apache-2.0); готовый код конвейера «страница → строки → текст» лежит в их демо
  [`Cyrillic-HTR-Demo`](https://huggingface.co/spaces/Kansallisarkisto/Cyrillic-HTR-Demo).
  После этого — псевдоразметка по статье.
- **Современная рукопись для предобучения:**
  - [Cyrillic Handwriting Dataset](https://www.kaggle.com/datasets/constantinwerner/cyrillic-handwriting-dataset) —
    73.8 тысячи фрагментов, CC0. Самая чистая лицензия; альтернатива или добавка к Peter для
    CRNN;
  - HKR — около 63 тысяч предложений, но лицензия CC BY-NC-ND и доступ по заявке;
  - [School Notebooks RU](https://huggingface.co/datasets/ai-forever/school_notebooks_RU) —
    около 1.9 тысячи страниц тетрадей, разметка по словам, MIT.
- **Дореформенный печатный текст**
  ([nevmenandr/russian-old-orthography-ocr](https://huggingface.co/datasets/nevmenandr/russian-old-orthography-ocr),
  MIT, Викитека) — источник текстов для синтетических строк и языковой модели.

Что говорят работы про дообучение TrOCR-подобных моделей на нескольких тысячах строк
исторической рукописи:

- полное дообучение работает: на 3.6 тысячи строк латыни XVI века — 2.55% CER, лучше
  Transkribus ([Ströbel et al., 2022](https://arxiv.org/abs/2203.11008));
- полностью замороженный энкодер сильно хуже (+8–10 п.п. CER), а LoRA не лучше полного
  дообучения ([Hüttner et al., 2025](https://openaccess.thecvf.com/content/WACV2025W/VISIONDOCS/html/Huttner_Low-Rank_Adaptation_vs._Fine-Tuning_for_Handwritten_Text_Recognition_WACVW_2025_paper.html));
- декодер важно учить, когда правила транскрипции отличаются от тех, что были при обучении
  ([Kohút, Hradiš, 2025](https://arxiv.org/abs/2503.19546)). Это наш случай: модель писала «е»
  вместо «ѣ».

Поэтому в E004 — полное дообучение и вариант авторов (сначала только энкодер), без LoRA и
без заморозки энкодера.

## Орфография

Исправлять дореформенную орфографию поверх ответа модели почти бесполезно. У готовой модели
это не больше 2.5 п.п. (19.5% → 17.0%, см. [E001](experiments/E001-kansallisarkisto-zeroshot.md#поможет-ли-исправление-орфографии-поверх-модели)).
Модели, обученные на нашей разметке, учат орфографию сами. Дореформенные словари и тексты
стоит использовать по-другому: как словарь или языковую модель при декодировании, которая
исправляет и ошибки чтения.

Что нашлось в открытом доступе (поиск 1 ноября 2026):

- **Конвертеры из современной орфографии в дореформенную.** Почти все слабые или закрытые.
  Самый осмысленный — [oldrus-ispell](https://github.com/winitzki/oldrus-ispell) (Perl, GPL,
  2001): ставит «ѣ» по словарю, а для неоднозначных слов (все / всѣ) выдаёт все варианты. В
  обратную сторону есть [prereform2modern](https://github.com/dhhse/prereform2modern) от
  ВШЭ (Python, MIT): с ним можно получить пары «современное — дореформенное» из любого
  дореформенного текста.
- **Словари.** В русском Викисловаре у лемм есть дореформенное написание (параметр `дореф=`,
  около 105 тысяч страниц, CC BY-SA), но его придётся доставать из дампа. Ещё есть словарь
  Даля в дореформенной орфографии в Викитеке.
- **Тексты для языковой модели.** В Викитеке в категории «Дореформенная орфография» около 46
  тысяч страниц, в том числе Военная энциклопедия Сытина 1911–1915 годов — те же годы, что
  Макаровка. Ещё есть датасет
  [nevmenandr/russian-old-orthography-ocr](https://huggingface.co/datasets/nevmenandr/russian-old-orthography-ocr)
  (MIT, около 3.9 ГБ): книги XIX века в дореформенной орфографии, картинки вместе с текстом.
- **Готовые модели.** Ближайшая по домену — модель Transkribus для русской рукописи 1910-х
  годов (архив Рычкова, CER 4.4%), но её веса не выложены.
  [trocr-prereform-orthography](https://huggingface.co/Serovvans/trocr-prereform-orthography)
  обучена на печатных книгах, не на рукописи.
- Работ, где дореформенный словарь или языковая модель при декодировании дали бы измеримый
  выигрыш в распознавании, мы не нашли. Значит, такой эксперимент — хороший кандидат на
  собственный вклад в диплом.

Как это применить: символьная n-граммная модель на текстах Викитеки и обучающих строках
Макаровки плюс beam search при CTC-декодировании CRNN. Ориентир — Digital Peter, где такой
приём снизил CER с 5.7% до 3.5%. Делать это имеет смысл после того, как будут результаты E003.
